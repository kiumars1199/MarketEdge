## Group 3: `claude/qa-d-kalshi-fetch` (on top of combos)

| Item | Status | Evidence |
|---|---|---|
| Every open market and event | Done | `pipeline/fetch_kalshi.py crawl` follows `/events?status=open&with_nested_markets=true&limit=100` (query unchanged from the proven one) through every cursor page. Guards: repeated cursor, 500-page cap, a failed later page keeps the pages before it (only a failed first page fails the stage). `meta.n_markets_open`, `n_events`, `pages`, `complete`. |
| Prices, volume, open interest, close time | Done | Each market row adds `no_bid_cents`, `no_ask_cents`, `last_price_cents`, `volume_24h`, `open_interest`, `status` (all nullable; both encodings read: `*_dollars` / `*_fp` strings and the older integers). `kalshi.json` keeps the 2,000 markets with the most volume (the file the app loads stays bounded); the full slimmed crawl goes to `data/kalshi_markets.json`, not uploaded. |
| Settlement results | Done | Every market seen open is remembered in `data/kalshi_known.json`. Once it is no longer open and past its close, the fetch asks for it by ticker (20 per call, 100 per run, least recently asked first, then oldest close, so a backlog of unresolved tickers never starves newer ones). A `result` of `yes`/`no` makes a `settled` row in `kalshi.json` (kept 7 days, max 500) and a line in `data/kalshi_settled.jsonl`. No result 30 days after close: dropped. |
| Backoff and a hard time budget | Done | The scan publishes after this step and `ops/scheduler.py` has no timeout, so the fetch has a wall-clock budget (`KALSHI_BUDGET_SEC`, default 45 s; crawl gets 70%). The budget is checked before each request and caps its timeout (per read, so a trickling response can overrun a little); 429/5xx back off with `Retry-After` but never sleep past it. Crawl, combos and settlements are separate stages: one failing or running out of time adds a `meta.notes` line and the rest still write. |
| Partial crawl never shrinks the file | Done | A crawl cut short (budget or a failed page) within 30 min of the last complete crawl keeps that crawl's other still-open markets, adds a note, and `fetched_at` takes the older time (`meta.complete_at` = last complete crawl). After 30 min without a complete crawl, the partial crawl publishes as it is. Every run starts at page 1, so if the full crawl never fits the budget it never completes: item 1 below. |
| Honest `fetched_at` | Done | The oldest response used (a cache hit counts at its cache time). Cache TTL 90 s (< the 120 s scan); cache files older than a day are pruned. |
| Data contract (rule 1) | Done | `apps/web/lib/types.ts` and `docs/03 § kalshi.json` updated together: new market fields optional and nullable, new `meta` fields optional, new optional `settled: KalshiSettled[]`.
